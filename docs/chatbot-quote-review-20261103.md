# 챗봇 팬트리·더도어 견적 조사 및 최소 변경 방향

검토일: 2026-11-03 · 상태: 조사 완료, 구현 전 검토안

이 문서는 변경 전 `47f4c3a`의 조사 기록이다. 후속 승인에 따른 구현·검증 결과와 남은 범위는 [후속 결과](chatbot-quote-followup-20261103.md)를 참조한다.

## 결론

현재 챗봇에는 팬트리·더도어 전용 계산 경로가 없다. 기존 행거 지침을 읽은 AI가 금액을 작성하고, 서버가 답변에서 숫자를 추출한다. **가격표만 추가하면 제품별 산식·배송비·할인·저장 금액의 일치를 보장할 수 없다.**

권고는 기존 1post 정책을 보존하면서 신규 제품을 명시적으로 구분하는 것이다. 단가·필수 질문·예상 견적의 한계는 지침으로 보완하고, 실제 자동 견적을 제공할 때는 입력 검증 → 결정적 계산 → 동일 결과의 표시·저장 경로를 작게 추가한다. 팬트리의 자동 칸수 산정까지 단순한 가격표 작업으로 취급하지 않는다.

쉬운 설명: 안내 문구를 고치는 일과 계산기를 붙이는 일은 다르다. 더도어는 비교적 작은 계산기로 가능하지만, 팬트리는 선반이 몇 칸 들어가는지도 정확히 알아야 한다.

## 확인된 현재 경로

### 1. 지침과 가격 정책

지침 폴더의 `.md` 21개는 모두 Git 추적 대상이며, 이 작업본에는 미추적·ignored 지침이 없다. 서버는 모델 호출마다 파일명순으로 전부 읽는다. 운영 배포본에 추가·변경된 파일이 있는지는 이번 조사로 확인할 수 없다. 저장소에 지침이 없다는 상태는 아니다. [S1]

| 항목 | 현재 챗봇 | 비교한 B2C main |
|---|---|---|
| 기본가 | 최대 4면 합산, 100mm당 10,000원. 정확히 50mm인 나머지는 내림 지시 | 50mm부터 올림, 기본가 최소 320,000원 |
| 팬트리 | 전용 제품·단수·칸수 산식 없음 | 실제 단수 2~7단, 전용 칸수 산정 사용 |
| 옵션 | 1post 2/3/4단서랍 99,000/119,000/160,000원 등 | 기존 옵션 및 팬트리 단수별 선반 추가금 |
| 11자 | 전용 추가 기둥 과금 규칙은 조사한 지침에 없음 | 추가 기둥 20,000원 1회 |
| 신축 | 고객이 신규아파트라고 언급하면 배송비 제외 10% 할인, 화장대 제외 | 새 견적 자동할인 없음. 과거 주문 재현에만 별도 할인 스위치 |
| 배송 | 시흥 무료 포함 권역표. 원칙은 총합 제외·별도 표기 | 공급금액과 배송비를 분리하고 배송 확정 시 최종 total에 합산 |
| VAT·시공비 | VAT 명시 없음. 통합 지침 예시에는 배송·시공비 포함 표현 | 결과 화면에는 방문 시공비·VAT 포함. 계산 함수에는 별도 VAT 가산 없음 |

이는 **채널 간 차이**이며, 챗봇 기존 견적을 B2C 정책으로 일괄 교체할 근거는 아니다. [S2, S7]

같이 로드되는 지침 자체에도 충돌이 있다. 별도 지침은 배송비 총합 제외·정식 견적 템플릿을 요구하지만, 통합 지침은 배송비 별도 분리를 금지하고 배송·시공비 포함 평문 예시를 준다. 견적서 생성용 스킬 문서도 일반 지침처럼 함께 로드되며, 텍스트 모드의 HTML 금지와 말미 HTML 출력 안내가 충돌한다. 새 파일 하나를 덧붙이는 방식만으로 우선순위가 해결되지는 않는다. [S2, S3]

### 2. 표시·저장 금액과 상품 구분

실제 고객 흐름은 `채팅 입력 → 모델 답변 → 상담 저장 → 견적 자동 접수 → 답변 표시`다. 모델 답변을 서버가 다시 산술 검증하는 단계는 없다. [S4]

| 경로 | 현재 동작과 영향 |
|---|---|
| 고객 채팅 | 답변 본문을 표시한다. 제품별 계산 결과 객체는 없음 |
| 금액 추출 | `총 합계 → 견적 → 할인 후 금액 → 최종 금액` 순서로 첫 매칭을 사용. 배송비·VAT·할인 포함 여부를 별도 보관하지 않음 |
| 상담 기록 | `견적서/주문서/주문내역`이 있는 최근 답변만 골라 `estimated_price` 저장 |
| 견적 접수 | `총 합계/견적서/주문내역` 중 하나와 추출 금액이 있으면 접수. **현재 quotes 쓰기 payload에는 금액 필드 자체가 없음** |
| CRM 설치 접수 | 이름·전화번호가 있으면 추출 금액을 `quote_amount`에 저장. 세션의 저장완료 플래그가 켜진 뒤 수정 견적은 재반영하지 않음 |
| 재방문 요약 | 형태·치수·색상·금액만 요약. 제품 종류·산식 버전 없음 |

접수 번호는 세션당 하나다. 같은 대화에서 제품을 전환하거나 견적을 수정하면 별도 견적 이력으로 분리되지 않는다. 상품은 대화 본문에 남을 수 있지만, 파서·접수 payload·재방문 요약에 구조화된 제품 구분이 없다. 신규 제품이 기존 드레스룸 견적으로 해석되지 않도록 이 경계를 함께 다뤄야 한다. [S5]

견적 오버레이는 전달받은 `summary.견적/배송비`를 표시할 뿐 계산하지 않는다. 현재 고객 채팅 코드에서 `openQuote`는 import만 있고 호출이 없으며 `/api/summarize` 호출도 발견되지 않았다. 남아 있는 요약 API는 관리자 인증을 요구하고, 추출 JSON 형식에 `견적` 필드도 없다. **이 오버레이를 현재 자동 견적의 중심 경로로 전제해 수정하지 않는다.** 별도 고객 견적 신청 폼도 계산기가 아니라 접수 경로다. [S6]

## 신규 제품별 최소 방향

### 팬트리

B2C 현행 경로는 오래된 `derivePantryShelves`가 아니라 전용 `pantryFill`을 사용한다. 일반 칸수와 코너 칸수를 나누며, ㅁ자는 출입 개방을 반영해 코너 3개다. 대표 이미지의 단수·칸수를 가격에 사용해서는 안 된다. [S8]

비교 코드의 산식은 다음과 같다. 챗봇에 적용할 정책으로는 별도 확정이 필요하다.

`기본가 max(100mm 반올림 단위수 × 10,000, 320,000) + 11자 추가기둥 + 일반칸수 × max(단수−3, 0) × 20,000 + 코너칸수 × max(단수−3, 0) × 30,000 + 선택옵션`

고정 검증 자료에는 19개 사례가 있으며, ㄱ자 1115/1235mm는 일반 2칸+코너 1칸이다. 7단이면 비교 산식상 기본가 320,000원+일반선반 160,000원+코너선반 120,000원=배송 전 600,000원이다. 이는 **비교 코드·fixture 기반 계산 예시**이며 새 챗봇 판매가 확정이 아니다. [S7, S8]

현행 구현의 코너 방향 탐색·짧은 면 처리 등은 단순 요약보다 복잡하다. 상단 주석의 짧은 코너팔 585mm와 실제 상수·fixture의 520mm도 다르므로 주석만 포팅하면 안 된다. 또한 계산기 자체는 분할 실패를 반환하지만 상위 액션은 일부 실패에서 안내와 함께 칸수 1·선반 추가금 없는 결과로 진행한다. 챗봇이 이를 완전한 팬트리 견적으로 복사해서는 안 된다. [S8]

**최소 제안:** 우선 제품·형태·면별 길이·실제 단수의 질문과 단가 설명을 분리한다. 자동 총액 제공은 검증된 칸수 산정 계약을 확보한 다음 연다. 칸수 미확정 상태는 금액 확정 불가로 처리한다. 이 단계에서 도면 생성·이미지 추천까지 이식하지 않는다.

### 더도어(2post)

제공된 결정문은 B2C 견적 전용 승인이다. 여기서는 신규 챗봇 산식의 제안 기준으로 삼으며, 챗봇의 기존 1post 할인·배송 정책까지 바꾸는 승인으로 확대하지 않는다. [S9]

- 모든 면의 길이를 먼저 합산한다. `자수 = max(10, floor((총 mm + 150) / 300))`, 기본가 `자수 × 120,000원`이며 일반문 포함.
- ㄱ자·ㄷ자 등을 포함한 형태는 길이 합산 견적만 제공한다. 실제 코너 시공 가능·도면 지원 확정으로 설명하지 않는다.
- 전용 추가금: 1단서랍 100,000원, 2단서랍 150,000원, 일반 추가선반 30,000원, 코너 추가선반 50,000원, 측판 110,000원, 이불반장 150,000원, 이불긴장 300,000원, 거울문/유리문 교체 짝당 110,000원. 선택 수량만 과금한다.
- 측판 자동 추가, 기존 1post 서랍 단가 적용, 임의 코너 공제·450mm 반올림·미정 옵션 가격 생성은 하지 않는다.
- 신규아파트 자동할인과 옛 실측·출장비 추가 과금은 해당 결정에 없다. VAT·시공비는 새 사실을 만들지 않고 적용 채널의 확정 문구와 맞춘다.

**최소 제안:** 검증된 면별 mm와 전용 옵션 수량만 받는 작은 순수 계산 함수로 시작한다. 합산·150mm 경계·최소 10자·옵션은 서버가 계산하고 AI는 설명을 담당한다. 자연어에서 추출한 값도 검증하며, 누락·모호 입력은 질문으로 되돌린다.

## 변경안 비교와 권고 범위

| 선택 | 가능한 범위 | 한계 |
|---|---|---|
| 지침만 보완 | 제품 구분, 단가 설명, 필요한 정보 질문, 미확정 시 담당자 확인 안내 | 자동 산술·칸수·출력/저장 일치 보장 불가 |
| 작은 계산 함수와 저장 연결 | 신규 제품의 검증된 입력에서 일관된 예상 견적 제공 | 팬트리 칸수 계약과 제품별 총액 정의가 선행되어야 함 |

낮은 우선순위 유지보수로서 **안내 보완 → 준비된 제품부터 자동 계산 연결**을 권고한다. 첫 구현에서도 기존 1post 지침·과거 금액은 보존한다. 신규 제품의 지침 적용 범위를 명시하고, 중복 통합 지침이 신규 산식을 덮어쓰지 않도록 관련 문구만 제한한다.

자동 계산 단계의 예상 변경은 서버의 해당 분기, 신규 계산 모듈 1개, 좁은 모의 테스트, 관련 지침으로 한정한다. 새 제품 결과에는 제품명·산정 기준·기본가·옵션·할인·배송·표시 합계의 의미를 함께 남긴다. 고객 출력과 `estimated_price`/CRM은 같은 결과를 사용하고, 저장 감지 조건과 수정 견적 반영도 맞춘다. 기존 `messages`에 산정 근거가 보존되는 방안을 우선 검토하며 전용 컬럼·DB 마이그레이션은 이번 최소안에 포함하지 않는다. 관리자 전체 개편·새 플랫폼·도면 엔진 이식은 필요하지 않다.

## 오프라인 검증 결과와 후속 검증

서버 파일에서 파서·저장 함수만 메모리로 추출하고 DB·알림을 가짜 함수로 교체했다. 서버 import·환경파일 로드·네트워크 호출 없이 다음 6개 관찰을 재현했다. 이는 기존 결함 재현이며 수정 통과를 뜻하지 않는다.

| 입력/상황 | 재현 결과 |
|---|---|
| `총 합계: 1,200,000원`만 있는 답변 | quotes 접수 호출 발생, 상담 `estimated_price=null` |
| `견적서`+할인 후 1,080,000원+배송 30,000원 별도 | 상담 금액 1,080,000원, quotes payload에는 금액 필드 없음 |
| 총 합계 1,200,000원과 할인 후 1,080,000원이 함께 있음 | 1,200,000원 우선 추출 |
| 같은 세션 견적 1,200,000원 → 1,350,000원 수정 | CRM 쓰기는 최초 1회, 금액 1,200,000원 유지 |
| `[금액]`/`[배송비]`만 있는 템플릿 응답 | 금액 추출은 가능해도 접수 감지 실패, 상담 금액 null |
| 상품명·면별 치수·예상 구성 템플릿 | 상품 구조화 없음, 해당 형식의 치수·옵션도 파서에서 누락 |

- **채널 정책:** 신규 챗봇 제품에 B2C 기준의 기본가 하한·할인·배송 포함 총액·VAT/시공비 문구를 적용하는지. 기존 1post까지 변경하는지는 별도 결정이다.
- **FAQ 우선 범위:** 인수 문서에는 확인 요구만 있고 원 결정문·적용 채널·발효 조건이 없다. 챗봇에도 FAQ만 제공하라는 뜻인지, 자동 견적 전 안내를 우선하라는 뜻인지 미확정이다.
