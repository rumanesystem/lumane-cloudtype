`#챗봇-모니터` Slack 채널로 들어오는 알림의 의미·발사 조건·대응 가이드. 새 알림 추가 시 본 문서도 같이 갱신.

## 채널

- 발신 코드: `server.js` 의 `notifySlack()` 헬퍼 (line 76 부근)

## 라벨 컨벤션

```
<이모지> *<이벤트명>* [<서비스>]
<본문 (멀티라인 가능)>
<어드민 바로가기>   ← ADMIN_URL env 설정 시 자동 부착
```

- 이벤트명은 Slack `*굵게*` 마크다운 — prefix 가 즉시 식별됨
- `<서비스>` prefix 로 향후 다른 서비스(예: `[lumane-server]`, `[notion-sync]`) 가 같은 채널 발신해도 분간
- 마지막 줄은 Slack 링크 마크다운 `<URL|텍스트>` — 알림에서 곧장 어드민 페이지로 점프 (env 미설정 시 생략)

## 에러 본문 4축 (장애 카테고리 공통)

장애 알림은 즉시 식별 가능하도록 4축 정보 노출:

| 축 | 예시 | 출처 |
|---|---|---|
| `status` | 401, 429, 529 | Anthropic SDK 의 `err.status` (HTTP) |
| `name` | `OverloadedError`, `RateLimitError`, `PostgrestError` | SDK 클래스명 (`err.name`) |
| `code` | PG 에러 코드 등 | `err.code` (있을 때만) |
| `err` | 원문 메시지 | `err.message` |

예시 메시지:
```
🚨 *LLM호출실패* [lumane-chatbot]
provider=anthropic status=529 name=OverloadedError
session=A1B2C3D4
err=Service overloaded — request was overloaded
<https://...cloudtype.app|어드민 바로가기>
```

```
💾 *DB저장실패* [lumane-chatbot]
ctx=AUTO_QUOTE session=A1B2C3D4
name=PostgrestError code=PGRST116
err=The result contains 0 rows
<https://...cloudtype.app|어드민 바로가기>
```

## 알림 추가 가이드 (개발자)

### 헬퍼 함수 시그니처

```js
notifySlack(event, emoji, body)
```

- `event` — 이벤트명, 액션 중심 한글 (예: `상담시작`, `DB저장실패`)
- `emoji` — 단일 이모지 (이벤트 종류 시각 식별)
- `body` — 멀티라인 가능. 첫 줄은 핵심 요약, 후속 줄은 상세

### 정책 체크리스트

새 알림 추가 시 아래 항목을 명시적으로 고려:

- [ ] **fire-and-forget** — `.catch(()=>{})` 로 Slack 장애가 챗봇 응답을 막지 않게
- [ ] **dedupe 정책** — 같은 이벤트가 짧은 시간에 폭주할 가능성 점검
  - 세션당 1회 (`sess.xxxNotified` 플래그)
  - IP 별 N분 쿨다운 (`Map<ip, timestamp>`)
  - 매 건 (폼 제출 같이 본질적으로 1회성 이벤트만)
- [ ] **재시도 후 실패만** — DB/외부 API 같이 재시도 가능한 경우 첫 시도 실패는 noise 라 알림 X
- [ ] **에러 본문 4축** — 장애 알림이면 `status`/`name`/`code`/`message` 포함
- [ ] **본 문서 갱신** — 알림 카탈로그 표에 한 줄 추가

### 환경 변수

| Key | 용도 | 비밀? | 등록 위치 |
|---|---|---|---|
| `SLACK_WEBHOOK_URL` | Slack Incoming Webhook | 🔒 시크릿 | GitHub Secrets + `deploy-main.yml` |
| `AI_PROVIDER` | 알림 본문의 LLM 제공자 표시 (기본 `anthropic`) | ❌ 평문 | `deploy-main.yml` 의 `value` |
| `ADMIN_URL` | 알림 끝에 부착할 어드민 페이지 링크 (미설정 시 링크 생략) | ❌ 평문 | `deploy-main.yml` 의 `value` |

**중요 — env SOT**: cloudtype 의 deploy workflow (`.github/workflows/deploy-main.yml`) 의 `options.env` 가 cloudtype console env 를 **배포 시마다 통째로 덮어씁니다**. cloudtype console 에서 직접 추가하면 다음 배포에 사라짐 → 항상 두 곳 동시 관리:
1. GitHub repo Secrets (시크릿 값) 또는 yml `value` (평문)
2. `deploy-main.yml` 의 `options.env` 리스트에 항목 추가

## 향후 후보 (Phase 2~)

본 문서가 다루는 1차 알림 셋 외에 검토 중:

- **Block Kit 카드형 포맷** — 주문서/장애를 카드로 (가독성 ↑)
- **Thread 묶음** — 같은 세션의 후속 이벤트를 첫 알림에 thread reply (`thread_ts`)
- **일일 다이제스트** — 매일 9시 KST cron 으로 전일 통계 (상담수/주문수/장애수/토큰사용량) 자동 발송
- **이상 패턴 감지** — 본문에 키워드 (`환불`, `클레임`, `사기`, `신고`) 포함 시 우선 알림 (@here)
- **Slack 인터랙티브** — 알림에 "어드민 takeover" 버튼 → 수신 endpoint 로 챗봇 모드 전환
